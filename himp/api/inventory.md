# Inventory API

This API endpoint is part of the Homelab Infrastructure Management Platform (HIMP).

## Purpose

Describe the purpose of the Inventory API.

## Endpoints

| Method | Path | Description |
|---------|------|-------------|
| GET | /inventory | Retrieve Inventory information |
| GET | /api/inventory/maintenance-readiness | List pending Ansible checks, endpoint reviews, and unreconciled outcomes for active hosts. Administrator access required. |
| POST | /api/inventory/hosts/{hostname}/reconcile-maintenance | Record an operator's verification for an unresolved plan outcome. Administrator access required. |
| POST | /api/inventory/sync | Synchronize inventory. Administrator access required. |
| GET | /api/inventory/identity/current | Compare active inventory with verified identities, plugin health, and report generation times |
| POST | /api/inventory/hosts/{hostname}/rename | Rename an active host with `new_hostname`. Administrator access required. |
| POST | /api/inventory/hosts/{hostname}/verified-move | Confirm continuity after an endpoint edit. Administrator access required. |
| POST | /api/inventory/hosts/{hostname}/verified-rebuild | Record an operator-verified replacement using `host_id`, `expected_incarnation`, and `replacement_verified: true`. Administrator access required. |

Rename preserves the stable host ID and the current incarnation, records the old
and new names, and carries the active maintenance policy forward. The rename uses
the recoverable inventory publication flow.

Record a rebuild after verifying that an installation was replaced. The operation
advances the incarnation only when the supplied ID and incarnation still match.
Existing evidence remains readable. The comparison endpoint includes only
evidence with verified attribution to a current incarnation.

## Notes

- Generated by HIMP Builder.

An address or SSH user change puts the endpoint under review. While review is
pending, maintenance skips the host and the comparison view omits its verified
evidence. The comparison view lists pending hosts and their current endpoint.
For a confirmed move, send `host_id`, `expected_incarnation`, `expected_ip`,
`expected_user`, and `continuity_verified: true` to the verified move endpoint.
For a confirmed replacement after an endpoint edit, include the expected IP and
user in the verified rebuild request.

Reports without a matching host identity are written under `reports/json/unverified`
and `reports/current/cmdb/unverified`. A report run cannot replace a canonical
report without a matching binding. The dashboard and host exports use unverified
output as a fallback when canonical output is absent. The verified comparison
view reads canonical JSON and checks the current host incarnation.

Current exports and dashboard reports require a matching stable host ID and
incarnation once identity is assigned. Generate a fresh report for a new
incarnation. Historical Markdown and JSON for a known host are available at
`GET /api/reports/host/{hostname}/history/{incarnation}`, with `?format=json`
for JSON. Older Markdown without identity metadata remains in the file inventory
and in writer backups after replacement.


Inventory Add/Edit can send `readiness: "verify"` to run bounded Ansible
fact gathering before publishing or `readiness: "pending"` to save a host
and prevent maintenance until verification succeeds. The UI sends one of
these modes on every save. An update rechecks the persisted hold at dispatch.

Reconciliation requires `host_id`, `expected_incarnation`, `expected_ip`,
`expected_user`, `plan_id`,
`plan_host` (the hostname recorded in the outcome), `note`, and
`confirm_drained: true`. Confirm the worker and remote operation have stopped
and verify the host state before submitting. The action preserves the original
outcome, uses the maintenance lock, and does not dispatch an update.
